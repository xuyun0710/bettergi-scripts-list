# 角色圣遗物总评分（BetterGI JavaScript 脚本）

按角色词条权重，把圣遗物副词条换算成评分，并累加成「5 件套装总分 / 毕业度」。纯本地计算，不上传任何数据，不改游戏文件。

## 一、评分口径

单件分 = Σ（副词条数值 × 基础单位分 × 角色权重 × 折扣）

基础单位分（提瓦特小助手同口径）：

| 词条 | 单位分 |
|---|---|
| 1% 暴击率 | 2.0 |
| 1% 暴击伤害 | 1.0 |
| 1% 攻击力 / 生命值 | 1.333 |
| 1% 防御力 | 1.067 |
| 1 点元素精通 | 0.333 |
| 1% 元素充能效率 | 1.205 |

- 固定值词条（小攻击 / 小生命 / 小防御）先按角色基准面板折算成等效百分比，再乘 `flatFactor`（默认 0.5，社区习惯折半）。
- 角色权重写在 `characters.json`：`0` 表示完全不算有效词条（例如那维莱特的攻击力%）。
- **主词条默认不计分**（可在设置里打开，按 0.33 系数折算，仅作参考）。
- 单件理论上限 9 词条 ≈ **59.4 分**，5 件满分 ≈ **297 分**；毕业度 = 总分 / 297。

单件分档：≥49 极品 / ≥40 优秀 / ≥30 良好 / ≥20 一般 / <20 偏弱
套装分档：≥80% 大毕业 / ≥67% 毕业 / ≥55% 良好 / ≥40% 及格

## 二、安装

1. 把整个 `ArtifactTotalScore` 文件夹放到：
   `BetterGI\User\JsScript\ArtifactTotalScore`
   （`User` 在 BetterGI 安装目录下，和 `Assets`、`log` 同级）
2. 打开 BetterGI → 调度器 → 添加脚本 → 选中「角色圣遗物总评分」。
3. 右键脚本 → **修改 js 脚本自定义配置**，选角色和运行模式，关闭即保存。

目录结构：

```
ArtifactTotalScore
├─ main.js           入口（评分内核 + OCR 流程）
├─ manifest.json     脚本描述
├─ settings.json     调度器里的配置项
├─ characters.json   角色词条权重表（可自己加角色）
├─ zones.json        OCR 区域与主/副词条判定阈值
├─ tools/selftest.mjs 评分内核自测（Node 运行）
└─ README.md
```

## 三、四种模式

### 1）连扫五件（推荐）
设置：角色 = 你要评的角色，模式 = `连扫五件（自动累加）`，连扫时长 = 90 秒。

流程：
1. 进游戏，打开该角色的圣遗物页
2. 启动脚本
3. 在 90 秒内，依次点开 5 件圣遗物的详情页，每件停留 2 秒左右
4. 脚本每 600ms 截一次屏，识别到「画面换了」才记为新的一件，同一画面重复不会重复计分
5. 满 5 件自动收尾，输出总分与毕业度

> 判定逻辑：同一件圣遗物需要连续两帧 OCR 结果一致才采纳，避免 OCR 抖动误判。

### 2）单件计分
点开一件圣遗物详情页 → 运行一次 → 记一件并累计。适合只想抽查一件，或者连扫时漏了某件补录。

### 3）标定区域（识别不准时用）
模式选 `标定区域（输出OCR坐标）`，脚本会把本次 OCR 到的每一行文本 + 坐标 + 解析结果打到日志窗口。据此：
- 看词条是否被完整识别（漏字就说明分辨率/缩放有问题）
- 若主词条混进副词条，打开 `zones.json` 的 `"useZone": true`，用日志里的坐标调 `substatZone`（x/y/w/h 均为画面比例，0~1）

### 4）查看 / 清空记录
`查看当前记录` 会输出该角色已记的每件分数与总评；`清空该角色记录` 把该角色分桶清空（不影响其他角色）。

```

  暴击率 7.8% → 15.60 分（权重 1）
  暴击伤害 14% → 14.00 分（权重 1）

  元素精通 23 → 3.83 分（权重 0.5）
  单件有效词条分：39.07（约 5.92 个词条，良好）

================ 胡桃 套装总评 ================
  已记录件数：3 / 5
  总评分（有效词条分）：118.42（约 17.94 个有效词条）
  毕业度：39.87% → 及格
  双爆总分：88.60
```

## 五、隐私与权限

- 不做任何网络请求，不读取账号信息。
- 唯一的写入操作是在脚本目录下生成 `score_state.json`（评分记录，已在 manifest 的 `saved_files` 中声明）。
- 卸载：删掉整个文件夹即可，`score_state.json` 也在这个文件夹里。

## 六、注意事项

1. **必须窗口化或无边框**：独占全屏下 BetterGI 抓屏容易黑屏。
2. 关闭游戏内 HDR、不要开滤镜/叠加色，OCR 对高对比度和彩色描边很敏感。
3. 有效词条只统计**副词条**；主词条需要手动开开关，且权重系数是参考值。
4. 4 星圣遗物只有 2~4 条副词条，评分天然偏低，别和 5 星直接比。
5. 权重是社区通用口径的近似，不同流派（如胡桃双爆流 / 精通流）期望不同，直接改 `characters.json` 对应数字即可，改完无需重启。
6. 想加新角色：复制一段 `characters.json` 里的条目改名，同时把角色名加进 `settings.json` 的 `character.options` 列表（不加也能用，只是下拉框里选不到）。

## 七、自测

评分内核与 OCR 解析逻辑抽在 `main.js` 的 `#region CORE` 段，可脱离 BGI 单独验证：

```
node tools/selftest.mjs
```

当前覆盖 23 项断言：词条解析（含全角符号）、主/副词条拆分、单件计分、零权重词条、固定值折算、套装分档。

另有端到端 dry-run，用假的 BGI 环境跑通「OCR → 解析 → 计分 → 存档」链路：

```
node tools/mockrun.mjs
```
